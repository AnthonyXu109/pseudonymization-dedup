# Supplementary analysis protocol, 2026-10-01

## Purpose and status

This is a pre-analysis specification for new follow-up work on the already
explored v7 paper. It does not retroactively preregister any v7 result. The
headline question is whether using one internal representation to decide
duplicates and a different document-scoped representation for publication
recovers copy detection without obscuring the cost of merging distinct cases.

## Fixed inputs and settings

- Primary input: TAB v1.0 at source commit
  `558e09e26d6b36f5f78440074e6a233946d98bd9`, first annotator's gold
  identifier spans, all 1,268 cases and the 400 paragraph copies generated by
  the v7 `build_corpus.py` with seed `20261001`. Verify the three input
  hashes against `../v7/pseudonymization-dedup/inputs_manifest.json` before
  analysis. The source repository explicitly licenses TAB under MIT.
- Word 5-gram sets, lowercased tokenization, exact Jaccard, threshold 0.7.
  No threshold selection using these follow-up outcomes.
- Decision representations: `RAW`, `SUR-DOC`, and `SUR-CORPUS`; final release
  representation for every row: `SUR-DOC`. Keyed representations are confined
  to the internal curation step; the fixed experimental key is for
  reproducibility, not a deployed security claim.
- Retention policy for TAB: keep each distinct case; versions of the same
  case may be merged. The copy relation follows the generated case IDs.

## Outcomes

1. Pipeline recall: proportion of the 400 copies in the same final connected
   component as their original. Also report direct-pair recall separately.
2. Distinct cases removed: original case IDs with no retained representative
   after one deterministic representative per component is chosen. Report the
   identity of each lost case for human policy review, not only the count.
3. Released-string equality: on the actual retained original cases after
   deduplication, calculate the published text's cross-document
   string-equality precision and recall for person mentions, using the v7
   definition. Report the number of evaluated true and predicted pairs.
   This is not a re-identification metric.
4. Paired differences and 95% intervals: resample components of the union
   graph from the two compared decision representations, keeping all records
   of a component together. The main table reports counts and intervals;
   seed `20261001` and 2,000 replicates are fixed before outcome access.

The substantive comparison holds the document set and final release
representation fixed. A row is not described as a policy improvement merely
because it has higher recall; its lost-case list must be examined too.

## Mechanism sensitivity

Use the same TAB cases and copies, never new generated copies. Compare
`SUR-DOC` with `SUR-CORPUS` under the same marked spans and one-token-per-token
replacement. For a controlled missed-span sensitivity, remove a prespecified
20% of marked entity IDs consistently within each document, then in a second
condition remove 20% of marked mentions independently. Use seeds 0 through 4.
Report pair and component recall, the fraction of pairs with inconsistent
within-document marking, and paired differences from the unperturbed spans.
These omissions simulate detection failure; they are not estimates of a
particular detector's error rate. The v7 detector results remain a separate
descriptive comparison.

## Human audit

The v7 table covers 185 distinct changed records across its sampled rows.
Generate a blinded review package for all 185, with record, actually retained
representative, policy text, and an `unclear` option. Never display strategy
names or earlier automatic labels before the reviewer exports judgments. The existing
91-item page oversampled automatically labeled boundary cases and cannot by itself
estimate the paper table's human-label proportions. Any summary must identify
the reviewing person and report unresolved items explicitly. Until human
judgments exist, the v7 labels remain AI-assigned.

## Reporting rules

- No new model, dense baseline, paid API, or training.
- Distinguish run-to-run MinHash ranges, cluster-resampling intervals, and
  uncertainty in human judgments; none substitutes for another.
- Call the full retention curve `distinct records removed`. Reserve harmful
  false removal for records supported by the stated policy and audit.
- Treat new analyses as follow-up on seen data. Document deviations in a
  new dated file; do not silently change this protocol.
